An AI agent that respects your terminal.

dev-cli explains why your last command failed, researches DevOps tasks, and — when you ask it to — autonomously fixes problems using structured tool calling. Local-first by default. Safe-mode is the default, not an afterthought.

What makes it different

Three principles, applied everywhere.

dev-cli is opinionated. Every command, every tool, and every autonomous action is shaped by the same three convictions.

Trust first

Safe-mode is on by default. 75+ shell danger patterns and 50+ sensitive-file globs are intercepted before any tool runs. Destructive actions need an explicit y from you. Every file change is snapshotted and reversible.

Local first

The default model is Ollama. Cloud (OpenAI-compatible or Perplexity) is opt-in per env-var. Set DEV_CLI_FORCE_LOCAL=1 and your code never leaves the machine.

Learn from success

Every successful fix is auto-recorded as a runbook keyed to your project's fingerprint. The next time the issue appears, dev-cli offers to replay the exact tool calls — without an LLM round-trip.

Commands

One CLI, focused tools.

Each command does one thing well, and they share the same safe-mode core.

dev-cli fix

Autonomous repair agent

Reads files, runs diagnostics, proposes fixes via structured tool calls. Approves nothing destructive without you.

dev-cli explain

Instant root-cause analysis

50+ built-in error patterns answer common failures offline. Falls back to the LLM only when no pattern matches.

dev-cli ask

Cheat sheets & research

Tool mode for instant cheat sheets; research mode for step-by-step solutions. Routes to Perplexity for time-sensitive queries.

dev-cli ui

Interactive dashboard

Bubbletea TUI with Agent, Containers, and History tabs. Mission control without leaving the terminal.

dev-cli doctor

Diagnose & auto-fix

Health-checks Docker, Ollama, GPU, network, and your LLM provider. --fix repairs what it can.

dev-cli runbook

Replay learned fixes

Inspect, replay, or prune the runbooks dev-cli captured automatically when previous fixes succeeded.

Safe mode

Hard guardrails. Soft prompts. Reversible by default.

An AI agent without safety is a liability. dev-cli intercepts destructive operations before they reach your shell.

  • ✓
    75+ shell danger patterns. rm -rf, dd, mkfs, force-push, drop database, system prune, kubectl delete --all…
  • ✓
    50+ sensitive-file globs. .env, *.pem, id_rsa, .aws/credentials, terraform.tfstate, …
  • ✓
    Severity levels. critical · danger · warning — with explanations the agent feeds back to itself.
  • ✓
    Diff sandbox. Every edit is snapshotted; review the cumulative diff before you walk away.
  • ✓
    One-keystroke rollback. Restores modified files; deletes ones the agent created.
  • ✓
    Dry-run mode. See exactly what the agent would do, without it doing anything.

How it works

A small, layered Go binary.

Cobra commands sit on top of a shared agent loop. The agent calls structured tools through a workflow engine that intercepts every destructive action.

Get started

Two commands, you're running.

dev-cli is a single Go binary. No CGO, no daemons, no telemetry. Pull a local model with Ollama and you're set.

Install
go install github.com/opx0/dev-cli@latest

# or build from source
git clone https://github.com/opx0/dev-cli
cd dev-cli && go build -o dev-cli .
First run
ollama run smallthinker
dev-cli doctor

# explain why your last command failed
dev-cli explain

# let the agent fix it
dev-cli fix "tests failing in auth module"

An agent you can leave running.

Trust comes from constraints. dev-cli's defaults are conservative on purpose — so you can spend the saved time on the work that matters.
